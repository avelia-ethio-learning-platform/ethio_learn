# Re-review after approval, resumable uploads, PDF → outline — 2026-09-24

Branch `deploy/render-vercel`. Three user-facing changes, plus the fixes an adversarial review
of them turned up. No new services, no manual migrations: `DB_SYNC=true` adds the new
columns/tables on deploy (all nullable or defaulted, safe on the existing production data).

**What you need to do:** rotate `GROQ_API_KEY` on Render (section 4). Nothing else is required.

---

## 1. Edits to an approved course go back to a quality officer

Before: once a course was published, every edit went live to learners immediately, unreviewed.

Now, on a **published or unlisted** course:

- **Edits are staged, not live.** Title/description/price/thumbnail, new or renamed sections and
  lessons, lesson summaries, replaced videos, deletions, new tutor notes and new assessments are
  stored beside the live course. Learners (catalog, course page, player, progress, certificates,
  tutor) keep seeing the approved version. The teach page shows the merged working copy with
  **New / Edited / Removing / New video pending** badges.
- **The educator submits the change set** ("Submit changes for review", with a change-log line
  and a "Major update — notify enrolled learners" box), can **withdraw** it to keep editing, or
  **discard** it. While it is in review the editor is locked.
- **The quality officer reviews a focused diff, not the whole course** — this is what keeps it
  fast without lowering the bar:
  - the QA queue shows the update as its own item (**Update** badge) with change chips
    ("+2 lessons", "1 video replaced", "price 400→500 ETB", "free preview added");
  - updates have a **24 h SLA** (new courses 48 h); the queue is ordered by deadline, and
    low-risk updates (no video, price or free-preview change, clean AI text screen) sort first —
    **nothing is ever auto-approved**;
  - "Review changes" opens a before/after page: metadata with word-level highlights, thumbnails
    side by side, the outline with + / − / ~ markers, lesson summaries before/after, a player for
    every new or replaced video (old and new side by side), new assessments **with their answer
    keys**, and new tutor-note excerpts;
  - **Approve stays disabled until every new or replaced video has been played**;
  - the AI plagiarism screen runs on the *changed text only*;
  - an officer **claims** an item (30 min) so two officers never review the same update.
- **Decisions:** *Approve* applies the whole change set atomically (one transaction; the course
  stays published — it is never re-published or taken offline), writes one change-log entry,
  and notifies enrolled learners only if the educator ticked "Major". *Request changes* returns
  it to the educator with notes (their staged work is kept). *Reject* discards the staged
  changes; the live course is untouched.
- **Institution courses** go through the institution admin first, exactly like a first submission.
- **Learner side effects on apply:** removed lessons are dropped from progress (completion is
  re-checked, so learners can complete a course whose last lesson was removed); a replaced video
  resets that lesson's watch position; learners who had completed see "new lessons were added
  since you completed".

Safety properties the review specifically tested and fixed:

- An approval only applies the **exact content the officer reviewed** (content hash checked on
  apply; a stale approval from an earlier submission is ignored).
- If the new assessments cannot be loaded (outcomes asleep on the free tier) the diff answers
  503 and Approve stays blocked — an unseen quiz can never go live.
- Only the assessments that were in the reviewed diff go live on approve.
- If an approved update cannot be applied, the educator is told to resubmit (never "your update
  is live" when it is not). "Your update is live" is sent only after it is applied.
- First-time submissions: withdrawing (or archiving) removes the item from the QA queue; a stale
  approve/flag after a withdraw is ignored; approving a post-publish re-check no longer re-sends
  "Your course is live 🎉".

## 2. Video upload with a progress bar that resumes where it left off

- Videos upload **straight to R2 in 8 MiB+ parts**, 3 at a time (2 on slow connections), with a
  progress bar showing **MB of MB, speed and time left**, plus **Pause / Resume / Cancel**.
- **Where it left off:** close the tab, lose the connection or reload — the lesson row shows
  "Unfinished upload: lecture.mp4 · 62% · Resume (choose the same file) · Discard". Choosing the
  same file continues from the parts the server already has (checked against the server, and
  against a fingerprint of the file so a different file with the same name never mixes in).
  Tested in a real browser: reload at 63 % → resumed from 50 % (the finished parts) → done.
- Flaky connections retry with backoff and pause (never silently fail) after 6 attempts; going
  offline pauses and resumes automatically; leaving the page mid-upload warns first; navigating
  inside the app keeps the upload running and re-attaches its progress.
- The server attaches the video to the lesson when the upload completes. "Add lesson" now creates
  the lesson first and uploads into it.
- Limits: mp4 / webm / mov / m4v (HLS `.m3u8` is no longer offered — there is no transcoding),
  **2 GiB** per video (`MAX_VIDEO_UPLOAD_BYTES`), up to 10 unfinished uploads per person
  (older than 24 h are cancelled automatically when that cap is hit). Thumbnails/photos ≤ 5 MiB.
- Learner project uploads got a progress bar and real error handling too.
- **Security fix found on the way:** a lesson could be pointed at *any* object key, including
  another educator's video. Lesson video keys must now be under the course author's prefix and
  must exist in storage. Upload URLs now also enforce the declared size and content type.

## 3. AI outline from a PDF / Word file — fixed

Your "it glitches when uploading a PDF" was real, with several causes:

| Problem | Fix |
|---|---|
| The hand-written PDF reader got usable text from **1 of 21** real PDFs (Chrome, Word, LibreOffice, Google Docs, InDesign, calibre… all produced junk or nothing); Word files crashed it | Replaced with **pdf.js** (Mozilla's reader, runs in a background worker) and **mammoth** for .docx — every PDF with a text layer now reads correctly; scanned PDFs get a clear "looks scanned — paste the text" message |
| The whole extracted text (up to 1.5 MB) was dumped into the text box → the page froze | Only a **digest** goes in the box: the document's outline (bookmarks / headings / numbering, incl. ምዕራፍ/ክፍል) plus proportional excerpts, ≤ 24 000 chars. A 51-page PDF reads in 1.3 s with no freeze |
| Long documents were rejected (40 000-char limit → 400, 100 kB body limit → 413) and the AI only ever saw the first 12 000 chars | Digest fits the limits by design; the AI sees the whole digest and is told the outline is authoritative |
| "Add all to course" fired one request per section and lesson → hit the rate limit and left half an outline | **One** request, all-or-nothing, and lesson summaries are kept |
| AI calls had no timeout (the proxy cuts at 30 s) | 25 s timeout with a clear message |

**Is there a generate-from-PDF feature?** Yes — on the course's manage page, "Generate an outline
with AI" (upload PDF/Word/text or paste notes). New: "Create and generate from a file" on the
new-course page opens it directly.

While the Groq key is expired, the outline is built from the document's own headings (and says
so). It is a reasonable starter; the real AI is better — see section 4.

## 4. Setup

1. **Rotate the Groq key (required for real AI):** new key at <https://console.groq.com/keys> →
   Render env group `ethiopialearn-shared` → `GROQ_API_KEY` → redeploy. Also update
   `.env.production.local`.
2. **Optional:** `MAX_VIDEO_UPLOAD_BYTES` (default 2 GiB) on the course service.
3. **Optional:** add Vercel *preview* origins to the R2 bucket CORS if you test uploads on preview
   deploys (today it allows `http://localhost:3000` and `https://ethio-learn.vercel.app`).
4. **Keep** the R2 lifecycle rule "Default Multipart Abort Rule" (7 days) — it cleans up uploads
   nobody finished.

## 6. Known limits

- Staged edits are per course, one open change set at a time.
- The "played every new video" gate is enforced in the officer's browser, not by the server.
- Unfinished-upload hints come from the browser that started the upload.
- There is still no video transcoding; upload MP4 (H.264) for the widest playback support.
- An assessment added to a live course that is later flagged/archived and returned to draft stays
  "pending review" after the course is live again, until the educator submits it as an update
  (the teach page offers that). It is never shown to learners unreviewed.
